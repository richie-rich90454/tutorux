# C++/Slint to TypeScript migration inventory

This is the authoritative feature-by-feature status for the rewrite. “Implemented” means the behavior is present in the TypeScript application and has a stated verification path; a format description or old C++ test alone does not count as a port.

Status values:

- **Implemented and verified:** replacement exists and the listed TypeScript verification passes.
- **Partial:** some user-visible behavior exists, but the original workflow is incomplete.
- **Not started:** no equivalent TypeScript workflow exists yet.
- **Desktop adapter required:** ordinary logic belongs in TypeScript, while the operating-system capability belongs behind the Tauri/browser adapter.

## Verification gates before removing C++/Slint

1. Port each partial/not-started row and add tests against existing C++ fixtures or generated legacy archives.
2. Run old/new differential checks for records, archive generations, imports, CLI JSON, errors, sort order, and state transitions.
3. Match encryption, crash recovery, file locking, archive maintenance, and transfer semantics before allowing writes to production archives.
4. Complete UI, accessibility, native file association, audio-device, and packaging checks on all three operating systems.
5. Update remaining documentation that describes old behavior, then remove CMake, Slint, WebAssembly, C++ sources, and obsolete dependencies only after the acceptance matrix is green.
